# Учёт рабочего времени

Небольшое веб-приложение для учёта времени сотрудников по задачам. Можно запускать и останавливать таймеры, а затем просматривать сводку и записи за выбранный период. Интерфейс работает на русском языке.

## Возможности

- Добавление сотрудников с проверкой уникальности имени без учёта регистра.
- Запуск и остановка одного активного таймера на сотрудника.
- Отчёты и список записей за период с учётом часового пояса клиента.
- Длительность активного таймера обновляется в интерфейсе.
- Хранение данных в SQLite с сохранением между перезапусками.

## Демо

Ссылка: _будет добавлена после деплоя_

Хостинг Render (бесплатный тариф): сервис засыпает после 15 минут без запросов, первое открытие может занять около минуты. Файловая система временная, поэтому база сбрасывается при перезапуске; в демо-режиме (DEMO_MODE=1) она автоматически заполняется вымышленными данными.

В демо-режиме отчёт по умолчанию показывает последние 7 дней, у одного сотрудника запущен таймер.

## Стек

Python 3.12, FastAPI, SQLite через стандартный `sqlite3` без ORM, чистые HTML/CSS/JavaScript без сборки, pytest.

## Запуск

### Windows PowerShell

```powershell
cd путь\к\time-tracker
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

### Linux/macOS

```bash
cd путь/к/time-tracker
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --reload
```

Откройте <http://127.0.0.1:8000>. По умолчанию база создаётся автоматически в `data/time_tracker.db`; данные сохраняются между перезапусками. Переменная `TIME_TRACKER_DB` задаёт альтернативный путь к файлу SQLite. Указанная папка создаётся автоматически.

Для локального демо перед запуском задайте `DEMO_MODE=1` (PowerShell: `$env:DEMO_MODE = "1"`; Linux/macOS: `export DEMO_MODE=1`).

## API

Ошибки возвращаются JSON-объектом вида `{"detail":"..."}`.

| Метод и путь | Назначение | Возможные ошибки |
|---|---|---|
| `GET /api/health` | Проверка доступности API | — |
| `POST /api/employees` | Создать сотрудника (`{"name":"..."}`) | 409 — имя занято; 422 — неверное имя |
| `GET /api/employees` | Список сотрудников и активных таймеров | — |
| `POST /api/employees/{id}/timer/start` | Запустить таймер (`{"description":"..."}`) | 404 — сотрудник не найден; 409 — таймер уже запущен; 422 — неверное описание |
| `POST /api/employees/{id}/timer/stop` | Остановить активный таймер | 404 — сотрудник не найден; 409 — нет активного таймера |
| `GET /api/entries` | Записи с фильтрами `employee_id`, `date_from`, `date_to`, `tz_offset` | 422 — неверный период или смещение |
| `GET /api/report` | Сводка за обязательные `date_from` и `date_to`, опционально `tz_offset` | 422 — неверные или отсутствующие параметры |

## Ключевые решения

- Один активный таймер на сотрудника обеспечен проверкой в коде и частичным уникальным индексом SQLite для защиты от гонок; конфликт возвращает 409.
- Время хранится в UTC. Клиент передаёт `tz_offset` в соглашении JavaScript `Date.getTimezoneOffset()`, а период считается по локальным суткам.
- Запись относится к периоду по времени начала; активная запись считается до текущего момента.
- Имена уникальны без учёта регистра через `name_key = name.casefold()`, в том числе для кириллицы.

## Использование ИИ

**Инструменты:** GitHub Copilot (agent mode) в VS Code с моделью ChatGPT 6 Luna — пишет и запускает код, выполняет ручные и браузерные проверки; Perplexity Computer (Claude Opus 5.5) — планирует архитектуру, формирует пошаговые запросы на английском и проверяет отчёт каждого шага.

**Процесс:** работа выполнялась в шесть шагов (каркас -> API -> исправления по ревью -> UI -> тесты -> README). После каждого шага агент предоставлял отчёт с кодом и выводами команд; отчёт проверялся, а найденные исправления включались в следующий запрос.

Примеры использованных запросов:

```text
If the employee already has a running entry -> 409 {"detail": "Timer is already running"}.
Also catch sqlite3.IntegrityError from the partial unique index and return the same 409.
```

```text
SQLite COLLATE NOCASE only folds ASCII, so "Иван Петров" and "иван петров" are both accepted.
Use name.strip().casefold() as a unique name_key.
```

```text
Add optional query param tz_offset (int, minutes, same sign convention as JS Date.getTimezoneOffset()).
Convert local midnight bounds to UTC before comparing started_at.
```

```text
REPEATED START while running -> 409 "Timer is already running", and the DB still has exactly ONE running entry for that employee.
```

Найденные и исправленные ошибки:

| Ошибка | Как обнаружена | Исправление |
|---|---|---|
| `init_db` не закрывал соединение: контекстный менеджер SQLite делает commit, но не close | Ревью агента | `contextlib.closing` |
| Pydantic не сериализовал `sqlite3.Row`, ответ завершался 500 | Ручная проверка API | Преобразование строки в `dict` |
| `COLLATE NOCASE` не учитывал регистр кириллицы: «Иван Петров» и «иван петров» считались разными | Ревью кода (Perplexity) | Уникальная колонка `name_key = casefold()` |
| Отчёт считался по суткам UTC: работа 00:00–03:00 по Минску попадала в предыдущий день | Ревью кода | Параметр `tz_offset` |
| `isoformat()` давал разный формат (с микросекундами и без) | Ревью кода | Единый `to_iso(timespec="seconds")` |
| `sqlite3 ProgrammingError` (`check_same_thread`) при параллельных запросах из браузера приводил к 500 | Проверка в браузере | `check_same_thread=False` для соединения на запрос |
| Введённое описание задачи пропадало при перерисовке списка | Ревью кода | Сохранение и восстановление значений полей |
| Встроенная валидация браузера блокировала «Выберите период»; ошибки валидации не переводились | Проверка в браузере / ревью | `noValidate` и перевод сообщений |
| Тест ожидал `+00:00`, а API отдаёт `Z` | Первый прогон тестов | Исправлено ожидание теста; ошибка была в тесте, не в коде |
| В демо отчёт по умолчанию (с понедельника) был пустым по понедельникам, т.к. демо-записи лежали в прошлых днях | Ревью кода (Perplexity) | В демо-режиме период по умолчанию — последние 7 дней + активный таймер в демо-данных |

Вручную проверялись ответы и статусы API, запуск/остановка таймера, отображение ошибки-дубликата, пустой период и безопасный вывод имени `<b>test</b>`. Браузерная проверка также подтвердила, что пользовательский текст отображается буквально, а не как HTML.

## Ограничения и дальнейшее развитие

- Сейчас нельзя редактировать или удалять записи.
- Запись, пересекающая полночь, относится к дню её начала.
- Имена с разным количеством внутренних пробелов считаются разными.
- Авторизация отсутствует намеренно.
- Возможные следующие шаги: редактирование записей, экспорт CSV, Docker.
